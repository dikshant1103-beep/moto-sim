**A laptop-class motorcycle simulation platform: PyChrono multibody physics, PINN tire models, a real-time Electron dashboard, a ROS2/Gazebo digital-twin stack, and a validation suite with published benchmarks.**

Positioning in one line: *the early-stage virtual workbench for two-wheeler teams who can't afford Adams/SIMPACK* — concept screening and target-setting on a laptop, feeding load cases to the certified CAE tools that do sign-off. Full honest positioning (what it is and isn't) in [`docs/POSITIONING.md`](./docs/POSITIONING.md); engineering detail in [`docs/TECHNICAL_HANDBOOK.md`](./docs/TECHNICAL_HANDBOOK.md).

## Components

| Dir | What it is |
|---|---|
| `core/`, `engine/` | PyChrono multibody motorcycle model + simulation engine |
| `rig/` | Virtual tire test rig — dataset generation, PINN training (`train_pinn.py`), Pacejka coefficient fitter (`train_coeff_fitter.py`) |
| `dataset/` | Trained tire PINNs + coefficient fitter (`.pt` and edge-ready `.onnx`); training CSVs/NPZ are regenerated by `rig/generate_*.py` (excluded from the repo) |
| `dashboard/` | Electron + React real-time dashboard (WebSocket telemetry) |
| `moto_gazebo/`, `moto_ros/`, `ros2_stack/` | ROS2/Gazebo digital-twin and AI-testing layer |
| `scenarios/` | YAML maneuvers (straight accel, corner entry) + road/track definitions |
| `validation/`, `docs/validation/` | Multi-axis credibility anchors — including a Whipple-bicycle benchmark reproducing published eigenvalues to 0.02% |
| `transport/`, `tools/` | Telemetry transport + report/utility scripts |

## Quickstart

```bash
# Physics backend (needs a PyChrono environment — conda recommended)
conda install -c projectchrono pychrono
python moto_sim_main.py

# Dashboard
cd dashboard && npm install && npm run dev

# Tests
pytest tests/ -q
```

The ROS2 stack (`moto_gazebo/`, `moto_ros/`) targets ROS2 Humble with Gazebo and runs
in a separate system-Python environment from the conda physics env — see
[`DEPENDENCIES.md`](./DEPENDENCIES.md).

## Validation stance

Numbers are only worth what their anchors are. The validation suite checks the model
against analytic and published references (Whipple benchmark, friction-locus and
lateral-force characteristics under `docs/validation/`) rather than asserting accuracy
by fiat — and the positioning doc is explicit that this is a screening tool, not a
homologation tool.
